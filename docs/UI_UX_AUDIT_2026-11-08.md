# AILISA Health Bridge UI/UX 巡查（2026-11-08）

## 使用者畫面的原則

首頁先顯示可理解的讀值、時間、趨勢及一句話說明。沒有可用讀值時顯示具體下一步。事件數、封包欄位、演算法版本及原始 log 僅放在資料來源或工程頁，不當成健康結論。研究訊號不可冒充經驗證的生理讀值。

## 這次已修

| 位置 | 發現 | 修改 |
| --- | --- | --- |
| 手機健康結論 | 大字顯示 ECG 事件數與技術結論 | 大字顯示健康讀值或重測；詳細來源按需開啟 |
| 手機健康首頁 | 血氧缺值時把原始資料放在主數值；ECG 顯示內部狀態 | 缺值顯示待量測或重測 |
| 手機 AI 分析摘要 | 研究事件數被當成摘要 | 摘要只顯示是否有可用健康結果 |
| 手機 ECG 卡片 | 原始資料計數出現在主要說明 | 改為簡短量測狀態與下一步 |
| 手錶 ECG 畫面 | 原始事件數與解析細節覆蓋結果 | 改為量測中、已取得訊號或本次無效 |
| 手錶量測頁 | 離腕提示說封包和研究資料 | 改為佩戴與重測指示 |

## 還需處理

| 位置 | 問題 | 處理方向 |
| --- | --- | --- |
| 手機 AI 分析 | 卡片過多，部分研究模型仍呈現工程用語；技術區雖已折疊但很長 | 逐卡簡化說明；將模型版本移到工程頁 |
| 手機與手錶進階感測器頁 | PPG、BioZ、溫度尚有無校準的原始訊號入口 | 明確標示可用讀值與未能換算的項目，避免把訊號稱作量測結果 |
| 手機運動分析 | 多個欄位逐項寫資料不足 | 以可用項目的趨勢摘要開頭，缺項集中列示 |
| 手錶 HRV、壓力 | 缺少實測 RR 時無法算出相應結果 | 將重測指示放在第一屏，確認資料來源及同步 |
| ECG | 目前收到的事件不符合原廠可解碼條件，不能可靠分為正常／異常 | 驗證原廠成功量測的輸出與本錶可用訊號，再接通結果流程 |

本次完成的是可讀性與狀態表達修正；不代表已取得原廠 ECG 分類能力，也不代表所有進階感測器皆已校準。
