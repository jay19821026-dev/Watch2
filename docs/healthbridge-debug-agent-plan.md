# Health Bridge Debug Agent Plan

## Objective

Improve measurement availability, data provenance, reliability, and battery behavior from fresh device evidence. Do not invent missing values, OEM calibration, or clinical validation. Unit-test and build success are not substitutes for phone/watch runtime verification.

## Roles

- **PM / delivery owner:** owns one objective, scope freeze, blocker/decision log, owner + due checkpoint per task, and acceptance evidence. PM rejects “built” as equivalent to “measured successfully.”
- **Codex technical lead / integrator:** owns source-of-truth inspection, device evidence, implementation, tests, artifact hashes, cross-role conflict resolution, and final decision. Only this role merges/reconciles changes.
- **Android/Wear OS engineer:** owns permission/lifecycle, Sensor HAL, Health Services and foreground-service correctness.
- **Data pipeline engineer:** owns acquisition→payload→quality/provenance→snapshot→Data Layer→phone persistence→freshness→UI trace.
- **Health research/calibration reviewer:** owns primary manufacturer docs, peer-reviewed methods, reference instrumentation and statistical study-design evidence; cannot invent OEM calibration.
- **QA:** owns black-box feature scenarios, permission-denied/charging/off-wrist/background/freshness UI acceptance and regression evidence.
- **QC / clinical-data integrity:** owns units, source, timestamp, quality/calibration gates, stale/rejected/missing classification and no-fabrication checks.
- **CI/CD and release engineer:** owns reproducible build matrix, unit/integration tests, lint, APK signing/version/hash, artifact provenance and install/release checklist. No publication without an explicit user request.
- **Security/privacy reviewer:** owns permissions minimization, local data retention, exported data/AI sanitization, notification privacy and threat review.
- **Battery/performance reviewer:** owns bounded sensor lifetimes, wakeups, Data Layer rate, notification defaults and measured battery comparison.
- **UX/accessibility reviewer:** owns watch-sized controls, contrast, readable states, errors and user-confirmed recovery paths.
- **Release/acceptance owner (PM + integrator):** signs the evidence checklist; the same person who authored a sensor calculation cannot be its sole verifier.
- **Claude, first-pass critic:** review a short de-identified change summary; identify concrete failure paths, disconfirming evidence, and missing artifacts. It does not receive repository source, device IDs, or raw health dumps.
- **ChatGPT, adversarial reviewer:** challenge causal claims, safety boundaries, notification side effects, and whether tests actually cover the claimed behavior.
- **Gemini Android-doc checker:** verify Wear OS, Android Sensor/HAL, Health Connect, and Data Layer statements only against official documentation.
- **Gemini failure classifier:** categorize acquisition, sensor mode/contact, signal quality, calibration, freshness, transport, persistence, and UI failures independently.
- **Gemini test designer:** produce minimal falsifying test cases and device validation steps.
- **DeepSeek pipeline reviewer:** inspect bounded parsing, serialization, Data Layer queue pressure, ordering, and backpressure.
- **Kimi literature checker:** find relevant peer-reviewed sensor/clinical methods; independently verify exact paper, DOI, population, and limitations before use.
- **Grok alternative hypothesis reviewer:** propose non-medical OS/platform/performance hypotheses, each independently checked against primary sources.
- **Meta AI UX reviewer (optional):** inspect user-facing clarity only; lowest-confidence input unless corroborated.

### Parallel review assignments

- For urgent permission/sensor incidents, dispatch separate PM, CI/CD, QA, QC, Wear OS, Android architecture, battery/notification, and integration-decision reviews. Keep each request bounded to a sanitized summary and a disjoint question; advisors do not concurrently edit the same files.
- PM tracks each item as `hypothesis → evidence → owner → test → acceptance`; QA checks behavior, QC checks data truth/provenance, CI/CD checks artifacts, and the integrator resolves disagreement. No role can approve medical calibration from consensus alone.

## Review protocol

1. Capture fresh phone/watch connection state, app versions, timestamps, recent crash/ANR buffers, battery state, and one bounded sensor export before changing code. Never call a stale snapshot current.
2. Produce a failure matrix per sensor: hardware/registration, callback count, payload shape, units/timebase, quality, OEM mode/contact, freshness, sync, storage, and display. Assign one evidenced failure class rather than a generic “data missing.”
3. Send the same minimal, de-identified technical question to reviewers. Never send personal health records, raw waveforms, device identifiers, account details, credentials, full source, or unpublished calibration artifacts.
4. Treat reviewer output as hypotheses. Verify it against source, official platform/OEM documentation, peer-reviewed studies, deterministic tests, and where relevant a controlled device/reference measurement.
5. Implement a narrow fix with a regression test. Run focused tests, full mobile/Wear tests, release builds, static checks, then verify on actual devices and inspect resulting logs/export. Report what remains unverified.
6. Preserve ordinary phone notifications as disabled by default; keep urgent user-safety events separate from routine alerts. Avoid persistent high-rate raw listeners and urgent Data Layer writes outside bounded user-started capture.
