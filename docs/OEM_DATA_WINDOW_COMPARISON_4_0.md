# Data-window audit / 資料時間窗對照

Checked against the locally decompiled Mi Fitness 3.59.2i APK on 2026-11-08. Paths below refer to local research material, not files shipped in this repository. Decompiled Java can misrepresent Kotlin boundaries; the statements here are limited to visible call paths. This audit does **not** establish the OEM's clinical decision window or signal calibration.

本頁對照 2026-11-08 本機反組譯的 Mi Fitness 3.59.2i。所列路徑是研究用本機素材，不隨 AILISA 發行。反組譯 Java 對 Kotlin 邊界可能失真；下表只記載能核對的呼叫路徑，**不能**據此宣稱掌握原廠臨床判讀窗或訊號校準。

| Data path / 資料鏈 | Decompiled evidence / 原廠依據 | AILISA correction / 修正 |
| --- | --- | --- |
| Heart rate → Health Connect / 心率同步 | `MiFitness-phone-installed-3.59.2i/decompiled/sources/com/xiaomi/fitness/repo/healthconnect/utils/HealthConnectTimeUtils.java`, `calcTimeRangeByUnSyncRecords`, groups unsynced entries into **30 minute** UTC anchored buckets. `.../biz/daily/HrSyncBiz.java`, `generateHealthConnectRecordByTimeRange`, creates one `HeartRateRecord` for a bucket and keeps **each** `HrItem.time` as a sample timestamp. This is a sync packaging window, not a heart rate decision window. | `AlgorithmicInsightsEngine` reads the record and checks every embedded sample's timestamp against the screen's query window. A record overlapping a boundary can no longer contribute out of range samples. / 心率逐筆樣本檢查量測時間，不用紀錄封裝時間代替。 |
| Seven calendar days / 近七個日曆日 | The OEM sync helper also exposes `divideTimeByDay`, while the same APK has distinct data and presentation modules. The inspected code does **not** prove a single OEM seven day analytics rule. | AILISA explicitly defines this screen as today plus six prior **local calendar dates**. Its prior `now − 168 hours` query conflicted with its own daily date buckets, discarding part of the first day; it now begins at local midnight and keeps the same start for heart rate, activity and trend inputs. / AILISA 此畫面採今日加前六個當地日曆日，全部共用同一起點。 |
| Sleep session / 睡眠區間 | `.../biz/daily/SleepSyncBiz.java`, `buildSleepSessionRecord`, writes actual segment start/end and stage start/end to `SleepSessionRecord`; no evidence supports dropping a session merely because it crosses a chart boundary. | AILISA keeps any session that overlaps the query interval, then clips its contribution when computing a displayed interval. Previously it discarded a session starting before the seven day boundary, even when sleep continued into the window. / 跨界睡眠先保留、計算時裁切。 |
| Temperature measurement time / 溫度量測時間 | Watch typed temperature flow is `XiaomiHealth-watch-decompiled/sources/.../health/temperature/TemperatureViewModel.java` → OEM service result `20500`; separate Android sensor channels appear in device `sensorservice`. The checked phone APK does not establish a common raw-to-°C conversion. | AILISA now accepts a documented Health Services data point clock as a measurement timestamp, alongside Android sensor event time. When only historical raw values remain, it selects the newest trusted record. Values stay labelled raw unless a unit and calibration are verified. / 辨識兩種可信量測時間；未驗證單位仍顯示原始值。 |

AILISA's 10 minute *current* sensor freshness gate and 30 hour *recent sleep* view are AILISA policies, **not** OEM windows. They must not be represented as copied OEM thresholds. Historical entries can still be displayed with their measurement time. ECG, BioZ and PPG raw event timing remains separately unverified where the device payload lacks a trusted sample clock; a 30 minute sync bucket does not repair that clock.

AILISA 的「目前感測資料 10 分鐘」及「近期睡眠 30 小時」是本程式政策，**不是**已驗證的原廠門檻。歷史值仍可附量測時間顯示。ECG、BioZ、PPG 若缺可信樣本時基，不能用心率同步封裝的 30 分鐘區間補足。

The phone home summary now applies the same overlap-and-clip rule to sleep-session fallback totals. Its label says *recorded interval*, because the OEM `SleepSyncBiz` uses bed/wake timestamps and stage records separately; the interval sum is not verified actual sleep. / 手機首頁的睡眠備援總時長也改為保留交集、按查詢界線裁切，並標明是紀錄區間，不能當作原廠實睡時長。

Mi Fitness's `Spo2SyncBiz.java` writes each `Spo2Item.time` as the `OxygenSaturationRecord.time` and its typed `spo2` value as `percentage`; the metadata modification time is separate. AILISA's phone home now checks this measurement time against its local seven-date query before selecting the newest oxygen record. The typed percentage remains separate from raw optical `65596` events. / 原廠逐筆血氧使用 `Spo2Item.time` 作量測時間、`spo2` 作百分比；AILISA 首頁先按該量測時間篩選，再挑最新紀錄，不將光學原始事件轉成百分比。

Mi Fitness's `repo/teperature/TemperatureBiz.java` aggregates typed `TemperatureItem` entries by their `time` for a daily report. The inspected `repo/healthconnect/biz/daily` package contains no temperature writer analogous to `Spo2SyncBiz`; this is a bounded source observation, not proof that Mi Fitness never exports temperature elsewhere. AILISA therefore labels a Health Connect temperature record by its actual data origin and does not present raw Watch 2 Pro sensor fields as the OEM daily temperature report. / 原廠溫度日報表依 `TemperatureItem.time` 整理；已檢查的 Health Connect 同步目錄未見對應寫入類別，不能據此宣稱原廠從不匯出。AILISA 的 Health Connect 溫度須標來源，手錶原始值不冒充原廠日報表。

The decompiled `TemperatureBiz.computeSummaryData` also keeps `TemperatureItem.bodyTemp` and `TemperatureItem.skinTemp` in separate summary fields, with separate positive-value checks. AILISA currently reads `BodyTemperatureRecord` with wrist measurement location from Health Connect. Its seven-date deviation is an AILISA descriptive median, not the OEM skin-temperature report or its averaging algorithm. The UI now names this source and distinction explicitly. / 反組譯的溫度日報表分別處理 `bodyTemp` 與 `skinTemp`；AILISA 讀的是 Health Connect 腕部位置的 `BodyTemperatureRecord`，其個人中位數差異不是原廠皮膚溫度日報表或原廠平均演算法，畫面已明確標示。

For OEM temperature charts, `TemperatureBiz.computeTimeDiffValueRecords` calls `BaseProcessBiz.groupByHour` for `home`, `groupByHalfHour` for `days`, and `groupByDay` for `weeks` and `months`. These are chart buckets for typed OEM temperature items, not calibration or a diagnostic window. AILISA's Health Connect detail now limits the wrist-temperature chart to wrist-location records and withholds a core-temperature reference score; it does not claim to reproduce these OEM chart buckets. / 原廠溫度圖表在 `home` 以小時、`days` 以半小時、`weeks`／`months` 以天分桶。這是原廠型別化溫度項目的圖表分桶，並非校準或診斷窗口。AILISA 的 Health Connect 詳細頁只保留腕部位置紀錄，不以核心體溫範圍評分；目前未宣稱重現原廠分桶。

Verification / 驗證：`mobile:testDebugUnitTest`, `wear:testDebugUnitTest`, `mobile:assembleDebug`, `wear:assembleDebug` passed after the window correction. `HealthInsightWindowPolicyTest` covers local midnight, daylight saving and a sleep session crossing the boundary. / 修正後雙端單元測試與 Debug 建置通過，測試涵蓋本地午夜、夏令時間及跨界睡眠。
