# PM handoff: watch/phone sensor failures

## Goal

Make every user-initiated scan auditable end-to-end on one session identity, with an honest terminal state per channel. Preserve old measurements as history, but never present them as results from the latest scan. A completed scan is not a clinically valid measurement.

- That 00:35 run used the charging-safe path: wrist-contact channels were skipped; 4 of 6 non-contact channels had raw events. The suite reported 18 missing terminal results. Across the 38-channel export, stage counts were 17 `snapshot_received`, 6 `no_events`, 15 `not_recorded`; these sum to 38.
- 18 channels had historical raw rows, 1 was fresh (passive Health Services heart rate), 17 were stale, and 0 passed the current quality-accepted counter. Raw/fresh does not mean calibrated or clinically valid.
- Nine HR packets were rejected as duplicate/older. This confirms rejection, not data loss; correctness needs a replay/order test.
- Phone system exits included memory-pressure kills and lock-screen cleanup; watch recorded low-memory. These are not app-crash evidence and are not yet linked causally to scan interruption. Older FGS permission errors and vendor Health Services crash are not attributed to this build.

## Shared definitions

- **Run complete:** a unique user-started session reached an explicit terminal state on watch and phone. It says nothing about whether a sensor produced data.
- **Channel received:** a new packet for that session passed payload/ordering checks and was persisted on the phone.
- **No event:** registration/attempt was recorded, the bounded acquisition window ended, and zero events arrived.
- **Skipped:** acquisition was deliberately not attempted (for example, wrist channels while charging), with a reason.
- **Not recorded / interrupted:** no terminal acquisition result exists; do not infer no event or sensor failure.
- **Fresh:** based on the measurement/event timestamp, not export or Data Layer receive time.
- **Physiological value available:** additionally requires supported channel mapping, valid units, signal quality, and device-specific calibration where applicable. Raw-only remains research data.

## Prioritized engineering work orders

### P0 — Session isolation and stale-row presentation

**Owners:** Wear + Mobile; QA verifies; PM tracks.

**Evidence:** watch sends `clear_sensor_snapshot` at scan start, but the phone control-status receiver does not consume it. Per-kind rows remain in preferences when a new scan does not report that channel. UI/export pairing is currently per-row/per-channel, not consistently tied to the latest suite. Control payload `success` is not persisted by the phone.

**Change:** add one explicit suite session ID/start time to scan-start, every channel snapshot/status, and terminal result. Keep historic rows but mark them `previous_session`; current-session cards and counters must exclude them. Persist run state and terminal reason separately from channel measurement/quality status. Do not clear long-term Health Connect data.

**Acceptance:** old-success → new scan → missing/partial channel leaves the old row visible only as historical; new session state is not overwritten by delayed old packets; export/UI agree on current vs historical; start, finish, cancel, timeout, and process-stop each produce an auditable run state.

### P0 — Terminal state and truthful completion

**Owners:** Wear; QA.

**Evidence:** progress/start messages use the same success boolean as terminal outcomes; service destruction cancels with `reportTerminal=false`; charging-safe/biomedical completion bases success on any raw events even when channels remain unreported.

**Change:** model `RUNNING / COMPLETE / PARTIAL / FAILED / CANCELLED / TIMED_OUT` explicitly. Define run completion by orchestration reaching a terminal state; report per-channel `RECEIVED / NO_EVENT / SKIPPED / FAILED / NOT_RECORDED` independently. Never equate one channel's raw event with all-scan success.

**Acceptance:** tests cover complete-zero-event, complete-partial, missing terminal, permission/start failure, cancellation, timeout, destruction, and charging skip. Phone UI says run state and per-channel reason without calling raw data a validated measurement.

### P1 — Sample-time and duplicate accounting

**Owners:** Mobile; QA.

**Evidence:** phone freshness currently uses packet timestamp in the raw row; watch also provides sample-time metadata. Nine duplicate/older HR rejections are not reconciled against source time and stored time.

**Change:** keep measurement/event time, watch enqueue time, phone receive time, and export time as distinct fields. Reject stale/duplicate packets idempotently with reason counters scoped to the session; do not increment accepted counts for replays.

**Acceptance:** duplicate replay is idempotent; strictly newer sample persists; old-session late packet cannot overwrite the current sample; delayed delivery with old measurement time remains stale; future timestamps are flagged.

### P1 — Acquisition and device acceptance

**Owners:** QA + Wear/Mobile; PM schedules hardware test.

**Change:** after P0 changes, perform one user-initiated, unplugged, snug-worn scan from the watch UI; compare same-session watch terminal/result → Data Layer receive → phone storage → UI/export. Capture only bounded, de-identified counts/state/timing in the work record.

**Acceptance:** every expected channel lands in exactly one state; no current-session channel is inferred from historical rows; service/registrations clean up after finish; no new fatal or duplicate notification; battery/temperature recorded before/after for a fixed short window. Report hardware evidence separately from unit/build tests.

## Regression matrix

| Scenario | Required result |
|---|---|
| old result, then new partial scan | old row remains historical; never counted current/fresh for the new run |
| same final snapshot replayed | no duplicate logical sample/count |
| new sample followed by older packet | newer sample remains; rejection reason is explicit |
| zero callbacks after registered attempt | channel `NO_EVENT`, not transport failure |
| charging guard | wrist channels `SKIPPED` with reason; no false sensor failure |
| service stop / timeout / cancellation | explicit run terminal state; partial data preserved, not called complete |
| export refreshed without new acquisition | export timestamp advances; measurement/session timestamps do not |

## PM release gate

Do not install/release based on compilation alone. P0 tests must pass, then paired-device UI acceptance must show matching session IDs and channel states. No claim of 100% detection, medical-grade output, or calibrated ECG/PPG/SpO₂/BioZ without device-specific evidence.
