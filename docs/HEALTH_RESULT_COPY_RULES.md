# 健康結果用詞規則 / Health result copy rules

作者：王宥傑。適用於手機、手錶、通知與每日報告的一般使用者畫面。

## 參照來源與界線

- 參照使用者提供的 Mi Fitness 健康摘要截圖（`docs/UI_UX_AUDIT_2026-11-08.md` 所述比較）與本機 Mi Fitness 3.59.2i 靜態追蹤（`docs/MI_FITNESS_3_59_2I_ECG_RECORD_PIPELINE.md`）。參照其**呈現順序**：短狀態、具體變化、圖表或詳情。
- 原廠 ECG 結果卡的短標籤來自原廠紀錄的 `analysisResult`，平均心率另列；原始 Android 感測事件數不是心律結果。不得複製原廠程式、字串表、專有判讀碼，或把其結果套在 AILISA 未驗證的資料上。
- 運動、步數、睡眠等趨勢可用已核實的時間窗與數值寫「近 7 天平均…，較前 7 天增加…」。沒有足夠的可比紀錄時，直接說明當前可用結果，不補造變化。

## 每張卡片的順序

1. **結論**：一個短詞或短句，例如「血氧偏低」、「心率在靜息參考範圍內」、「本週步數增加」。正常／異常只在來源、量測情境、單位與適用參考界線都成立時使用。
2. **依據**：一個讀值或一個有明確時間窗的變化，例如「94%」、「近 7 天平均 6 小時 23 分，較前 7 天增加 56 分」。不要同時堆來源 ID、事件數和多組研究指數。
3. **行動**：只有需要時提供一個主要動作，例如「重新量測」、「查看趨勢」或「檢查同步」。警語只放在相關結果或詳情頁，簡短明確。

## 可直接套用的用字

| 狀態 | 主要畫面 | 下一步 |
| --- | --- | --- |
| 已驗證且可比較的讀值在適用範圍內 | 「在參考範圍內」並顯示讀值 | 「查看趨勢」 |
| 已驗證且可比較的讀值超出適用範圍 | 「偏高」或「偏低」並顯示讀值與參考範圍 | 「重新量測」；持續異常或不適時提示就醫 |
| 有讀值但情境不明，例如未標記靜息的心率 | 顯示讀值與時間，不判成靜息心率正常／異常 | 「查看趨勢」或「安靜休息後重測」 |
| 量測未完成、訊號品質差 | 「這次量測未完成」或「訊號不清楚」 | 「戴好手錶並重新量測」 |
| 原始訊號已收到但尚不能換算生理結果 | 「已取得訊號，尚無可解讀結果」 | 「查看原始資料」或「重新量測」 |
| 尚無紀錄、資料過期或同步失敗 | 分別寫「尚無紀錄」、「這是較早的紀錄」、「尚未同步到手機」 | 對應量測、刷新或同步動作 |

ECG 沒有可解讀波形時，不寫「心臟正常」、「心率不整」或「心房顫動」，也不把事件數當結論。若有經驗證的分類，先顯示分類，再分開顯示心率與波形；若沒有，主畫面只留一句原因與重測動作。

## 禁止出現在主要健康結論的內容

- 「216 個事件」、「2974 個原始點」、「可比較 0/11 項」、「source=…」、「timestamp_source=…」、例外類別名、解碼欄位、模型版本或整段檢測流程。
- 「資料不足」作為單獨結論；要說清楚是未量到、訊號不清楚、紀錄太舊、尚未同步，還是此裝置不支援。
- 沒有讀值時用長篇免責文字填滿畫面；沒有足夠證據時硬寫正常／異常或疾病名稱。
- 同一卡片反覆顯示多個同義警語、來源限制及工程狀態。

工程資訊保留在明確標示的「資料來源／技術詳情／匯出」頁，並維持可追溯性。修改文案時須檢查首頁、詳情、量測完成、歷史、通知、每日報告與手錶端是否使用一致的狀態。
